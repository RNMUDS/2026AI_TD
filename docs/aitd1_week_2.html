復習プレゼン：教師あり学習の「モデル学習サイクル」（20分）

第1回 GW1-3（順伝播と誤差逆伝播）の流れを、presenter と implementer の2人が別のグループのメンバーに説明する。その前にグループで相談し、2人が話せるように鍛える。シートや画面は見ない。口頭で話すか、ホワイトボードに図を描きながら説明する。

役割を担当する

  • implementer（インプリメンター）：コードを書く（1人だけ）。TODO の中身を考えてグループに見せる
  • verifier（ベリファイアー）：条件を変えて再実行し、結果を疑う
  • recorder（レコーダー）：討議で出た意見と結論をまとめ、プレゼンで伝える
  • presenter（プレゼンター）：司会・時間管理をし、結論を一文で発表する

3人グループは verifier が presenter を兼ねる。5人グループは verifier を2人にする。最初に決める。復習プレゼンは presenter と implementer が行う。ノートブック (0) の MEMBER_ROLE は準備のときに自分の役割に書き換える。

ex2.ipynb の (5) では、.pt ファイルに形の情報（hidden など）も一緒に保存してある。そこで先に torch.load で読み、その情報を使って build_model(...) が Net() の代わりに同じ形を用意する。TODO 1 は torch.load と load_state_dict の2行。

討議：hidden とは何か（(5-2)・3分）

(5) の出力では、3つともパラメータ数は約30万なのに、hidden が 357・152・999 とばらばら。(5-2) で層ごとの重みの形と数を見て話す。

  1. hidden は、それぞれのモデルで何の数か
  2. 同じ約30万にそろえたのに、なぜ hidden が3つで違うのか（hidden を1増やすと、重みはいくつ増えるか）
  3. 3つに共通する大きな重みはどれか。何のための重みか
  4. パラメータ数が同じなら、計算の量やメモリも同じになりそうか（→ (9) で確かめる）

バッチサイズ（ミニバッチサイズ）とは（(9-2) で使う）

  • ミニバッチ：データ全体（ここではテストデータ 1,821文）を分けた、モデルに1回でまとめて流す文の束
  • ミニバッチサイズ：1つのミニバッチに入れる文の数。64 なら64文ずつ29回に分けて流す
  • バッチサイズ：本来「バッチ」はデータ全体のことだが、PyTorch の batch_size をはじめ、ミニバッチサイズのことを単にバッチサイズと呼ぶのが普通。この授業でも同じ意味で使う
  • バッチサイズを 1821 にすると、ミニバッチ＝データ全体になり、1回で全部を流す
  • どのバッチサイズでも、最後に出る正解率は同じ。違うのは1回の計算で同時に扱う量。モデルは流した文の数だけ途中の計算結果をメモリに置くので、バッチサイズが大きいほど推論中のメモリが増える

第1回 GW3 の DataLoader(..., batch_size=64) の batch_size と同じもの。(9-2) で、バッチサイズを変えたときにメモリが何倍になるか、どのモデルで一番増えるかを測る。

考察のための手がかり：Adam の一歩

Adam は勾配 g をそのまま使わず、過去の勾配の平均 m と、勾配の2乗の平均 v を使って W ← W − lr × m ÷ (√v + ε) と一歩を決める。m と √v は、どちらも勾配と同じ「大きさ」を持つ。割り算すると何が起きるか。(9-2) では、勾配が1万倍違う2つの重みを Adam と SGD で1歩ずつ動かして確かめる。
