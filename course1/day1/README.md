各演習は「実行 → グループディスカッション → グループ内プレゼン」を 1 セットとする．討議の問いはノートブック末尾のブロックに書いてあり，presenter が進行し，recorder が討議メモを埋める．

レポートは **自班の実測 ＋ 質問カード交換で集めた 3〜4 班の実測値** を比較して作成する．提出された班の分は教員が統合図として全体共有で投影し，統合 CSV を授業後に配る（集めきれなかった分はそれを使ってよい）．

## 演習の進め方

1. ノートブックの **(0) 班と役割の設定** で `GROUP_ID` と `MEMBER_ROLE` を書き換える
2. ブロックを上から順に実行し，`TODO` を埋める．**implementer だけがコードを書く**
3. verifier は implementer の隣で条件を変えて再実行する（例：バッチサイズ，繰り返し回数）
4. recorder は出たエラーと直し方，討議で割れた点を `results/` に残し，そこから他班への質問を 3 問作る（`waiting_task.md` 参照）
5. presenter は討議の進行と時間管理を行い，班の結論を一文にまとめ，プレゼンと全体共有で班を代表して話す．質問カード交換では他班 3〜4 班分の実測値を集める

**班が 3 人のとき**：presenter を verifier が兼任する（`MEMBER_ROLE` は "verifier"）．3 役を日替わりで回す．
**班が 5 人のとき**：5 つ目の役割 **collector**（収集係）を置く．質問カード交換で他班 3〜4 班分の実測値（演習2 の表と演習3 の順位）を集め，時間管理も担う．implementer は増やさない（コードを書くのは 1 人のまま）．

### 演習1（E1-1）環境ベンチマーク

自分のマシンの帯域（GB/s）・演算（GFLOPS）・学習ステップ時間（ms/step）を測り，CSV に投稿する．
要点は **(4) 同期しないと何が起きるか**．MPS では同期の有無で 10 倍以上異なる．

### 演習2（E1-2）学習済みモデルの同時測定

A1（埋め込み平均＋MLP）・A2（1次元畳み込み）・A3（小型 Transformer）はパラメータ数を約 30 万に揃え，
同じデータ・同じ条件で学習済み．正解率・損失・推論時間・メモリを **同じ関数で** 測って 1 枚の表にする．
**実行前に `waiting_task.md` の予測欄を埋める．**

### 演習3（E1-3）「良いAI」の定義と順位

班で「良いAI」を一文で定義し，正規化の方法（minmax か rank）を選び，4 指標に重み（合計 1）を付けて順位を出す．
**他班と順位が食い違うこと** を次のプレゼンで確認する．同じ数値から違う結論が出る理由を話す．

## 班別条件

なし．演習3 の重み付けのみ班が自由に決める（`conditions.yaml`）．

提出は **zip にせず，上記のファイルをそのまま個別に** LMS の課題へアップロードする（班の implementer が 1 人で提出し，他の 3 名は提出しない）．ファイル名の班番号は変えない．教員側は「すべての提出をダウンロード」した zip を `instructor/import_lms.py` で `results/` に取り込み，`verify.py` と `aggregate/` をそのまま回す．

## グループ内プレゼン（各 10 分，スライド禁止，画面を見せて話す）

presenter が班の結論を 2 分で話し，他の 3 名が 1 分ずつ補足する．残り 5 分は質疑．

| 役割 | 話すこと |
|---|---|
| implementer | どの TODO で行き詰まったか．同期を入れる前後で数値がどう変わったか |
| verifier | 条件を変えて何が変わったか（繰り返し回数，バッチサイズ，指標の向き） |
| recorder | 出たエラーと直し方，討議で割れた点，そこから作った他班への質問 3 問 |
| presenter | 班の結論（一文）と，その根拠となる数値 |
